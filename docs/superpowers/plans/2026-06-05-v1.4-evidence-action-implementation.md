# V1.4 取证行动台实施计划

日期：2026-06-05

## 目标

在现有 NewCar 项目中实现 V1.4 的第一阶段：候选详情页“取证行动台”。它把质量、三电、红线、风险和工作流缺口转换为可复制的商家沟通、检测复检和合同备注清单。

## 实施步骤

1. 静态测试先行
   - 在 `scripts/tests/ui-static.test.mjs` 增加测试，确认存在：
     - `buildEvidenceActionPlan`
     - `renderEvidenceActionPanel`
     - `formatEvidenceActionPack`
     - `copyEvidenceActionPack`
     - `#evidenceActionPanel`
     - `.evidence-action-panel`
     - `data-copy-evidence-pack`

2. 页面结构
   - 在候选详情主列中，于“质量与三电”后新增“取证行动台”面板。
   - 面板头部提供“复制取证包”按钮。
   - 面板内容由 `#evidenceActionPanel` 渲染。

3. 数据与逻辑
   - 新增 `buildEvidenceActionPlan(car)`：
     - 输入候选车。
     - 读取质量评估、红线、风险、工作流、信息墙和车源字段。
     - 输出 readiness、gate、blockers、sellerQuestions、inspectionQuestions、contractClauses、nextSteps。
   - 新增 `formatEvidenceActionPack(car, section)`：
     - 输出完整 Markdown 或单分组文本。

4. 渲染与交互
   - 新增 `renderEvidenceActionPanel(car)`。
   - 在 `renderDetail()` 中更新 `#evidenceActionPanel`。
   - 事件委托支持 `data-copy-evidence-pack`。
   - 顶部按钮 `#copyEvidenceActionPack` 支持复制完整包。

5. 样式
   - 新增 `.evidence-action-*` 样式。
   - 桌面端三列清单，移动端单列。
   - 风险状态使用现有颜色体系。

6. 验证
   - `node --test scripts/tests/ui-static.test.mjs`
   - `node --test scripts/tests/*.test.mjs`
   - `node --check app.js`
   - 本地浏览器检查桌面与移动布局。

## 不做

- 不新增后端 API。
- 不重构全站信息架构。
- 不把 AI 检索结果直接写成事实；仍维持待核验分层。
