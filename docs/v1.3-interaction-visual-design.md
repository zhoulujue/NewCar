# NewCar V1.3 交互与视觉设计文档

日期：2026-06-05

## 0. 设计目标

V1.3 的界面目标是把 NewCar 设计成一个安静、可靠、证据驱动的购车尽调工作台。它不应该像汽车资讯站，也不应该像营销落地页；它应该更接近一个为个人购车决策定制的专业工作台：

```text
发现值得看的车 -> 加入候选尽调 -> 补齐证据 -> 关闭风险 -> 做出购买节奏判断
```

设计关键词：

- **清醒**：每个页面都告诉用户当前结论、缺什么、下一步做什么。
- **克制**：视觉不浮夸，减少大色块和装饰，优先信息密度与可读性。
- **可信**：AI 结论、质量数据、商家背调都必须展示来源、状态和置信度。
- **从容**：用户有接近一年的指标窗口，界面要支持长期观察，而不是制造紧迫感。
- **移动友好**：真实使用场景大量发生在手机上，看车源、截屏、上传、问商家、试驾记录都要顺手。

## 1. 设计方向选择

### 方案 A：证据中枢式工作台

以总览、候选详情和证据状态为核心。所有页面围绕“当前是否可买、还缺什么证据”组织。

优点：

- 最贴合 V1.3 的证据驱动定位。
- 能解决当前风险、质量、信息墙分散的问题。
- 对二手车源特别有效。

缺点：

- 初次进入会显得偏严肃，需要用视觉层级减少压迫感。

### 方案 B：购车管道式 CRM

以阶段看板为核心，把候选分成观察、补证、试驾、谈价、可买、放弃。

优点：

- 非常适合长期选车。
- 用户能快速知道每台车在哪个阶段。

缺点：

- 如果单独采用，会弱化“质量与三电”“信息墙”这些深层证据。

### 方案 C：车型库 + 参数对比式

以车型列表、参数卡、横向对比为核心。

优点：

- 容易实现，也符合传统汽车工具直觉。

缺点：

- 和用户现在的真实痛点不匹配。
- 容易再次把新车、二手、单车证据混在一起。

### 推荐方向

采用 **A + B 的混合方案**：

> 总览是证据中枢，候选库是阶段管道，单车详情是尽调工作台。

也就是：

- 总览回答“今天该做什么”；
- 发现页回答“哪些新车/二手值得加入”；
- 候选尽调回答“每台车推进到哪一步”；
- 单车详情回答“这台车能不能买”；
- 信息墙和质量模块成为所有判断的证据底座。

## 2. 信息架构

### 2.1 桌面端主导航

V1.3 桌面端建议使用左侧导航，但减少一级入口数量，避免功能看起来碎。

主导航：

1. **总览**
2. **发现**
3. **候选尽调**
4. **对比**
5. **试驾**
6. **商家**
7. **报告**

二级入口：

| 主入口 | 二级内容 |
|---|---|
| 总览 | 今日结论、待办、指标倒计时、AI 任务、重点风险 |
| 发现 | 新车观察、二手车源、重点车型池 |
| 候选尽调 | 阶段看板、候选列表、单车详情、信息墙、质量与三电、风险闭环 |
| 对比 | 候选横向比较、i6 标尺、成本、质量、风险 |
| 试驾 | 试驾脚本、试驾记录、i6 相似度 |
| 商家 | 商家档案、承诺清单、关联车源 |
| 报告 | 成交前红线检查、决策报告、导出 |

设计理由：

- “新车观察”和“二手车源”合并到“发现”，但内部必须明确分 Tab。
- “待关闭风险”不再作为主导航常驻入口，风险进入总览和单车详情，减少一个孤立页面。
- “质量与三电”不做独立主导航，而是每个候选的核心模块。

### 2.2 移动端主导航

移动端底部导航保留 5 个以内：

1. **总览**
2. **发现**
3. **尽调**
4. **试驾**
5. **更多**

移动端映射：

| Tab | 内容 |
|---|---|
| 总览 | 今日结论、关键待办、指标倒计时 |
| 发现 | 新车观察、二手车源 |
| 尽调 | 候选列表、单车详情、风险、信息墙、质量 |
| 试驾 | 试驾任务、试驾复盘 |
| 更多 | 画像、商家、报告、导入导出、账号 |

交互要求：

- Tab 切换保留各自滚动位置。
- 新车/二手在“发现”里用顶部 segmented control 切换。
- 候选详情从列表进入后，返回列表保留滚动和筛选。
- 单车详情内使用分段锚点：概览、质量、信息墙、风险、成本、试驾。

## 3. 全局交互模型

### 3.1 三层对象

界面所有卡片都要显式区分三层对象：

| 层级 | UI 标识 | 主操作 |
|---|---|---|
| 车型 | 新车车型 | 加入新车候选、查看时间线 |
| 车源 | 二手车源 | 加入尽调、打开外部车源 |
| 候选 | 尽调对象 | 补证、关闭风险、生成报告 |

视觉标识：

- 新车车型：蓝色轻量标签。
- 二手车源：绿色轻量标签。
- 手动候选：灰色轻量标签。
- 红线风险：红色文字和浅红底，不用大面积红色。
- 待核验：琥珀色。
- 已证实/已关闭：绿色。

### 3.2 页面状态

每个主要页面都必须有 4 类状态：

1. **结论状态**：当前系统怎么判断。
2. **证据状态**：判断来自什么证据，证据是否完整。
3. **动作状态**：下一步该做什么。
4. **系统状态**：AI/数据刷新是否成功、失败、过期。

示例：

```text
结论：继续观察，不建议现在下订。
证据：质量数据缺 SOH 和三电质保证据。
动作：向商家索要 4S 维保、SOH、检测报告完整页。
系统：质量数据 06/05 10:30 刷新，车源状态 6 天未复核。
```

## 4. 视觉系统

### 4.1 整体气质

界面应呈现“安静的专业感”，而不是“新能源发布会感”。

建议视觉方向：

- 背景：冷白到浅灰，降低视觉噪音。
- 主色：深青绿色，延续当前 `#0f766e`，表达可靠和行动。
- 辅助色：蓝色用于信息，琥珀色用于待核验，红色用于红线。
- 文本：深石墨色，避免纯黑造成压迫。
- 卡片：白底、细边框、轻阴影，圆角不超过 8px。
- 图片：真实车辆图片是视觉主角，不用装饰性背景。

禁止：

- 不做大面积渐变背景。
- 不做营销式 hero。
- 不使用装饰性圆球、光斑、复杂玻璃拟态。
- 不把页面 section 包成大浮卡再嵌套小卡。
- 不用过多彩色标签堆叠。

### 4.2 颜色 Token

```css
--bg: #f5f7f9;
--surface: #ffffff;
--surface-soft: #f9fafb;
--text: #16202a;
--muted: #687382;
--line: #dfe5ec;
--primary: #0f766e;
--primary-strong: #0b5f59;
--info: #2563eb;
--success: #167145;
--warning: #b54708;
--danger: #b42318;
--nav: #101820;
--radius: 8px;
```

色彩使用规则：

- 主按钮只用 primary。
- 次按钮用浅灰背景或白底边框。
- 风险状态使用文字 + 浅底，不使用整卡强红。
- 同一卡片内状态色不超过 2 种。

### 4.3 字体与层级

建议层级：

| 用途 | 字号 | 字重 |
|---|---:|---:|
| 页面标题 | 28px 桌面 / 22px 移动 | 750 |
| 模块标题 | 18px | 700 |
| 卡片标题 | 16px | 700 |
| 正文 | 14-15px | 400-500 |
| 辅助文字 | 12-13px | 400 |
| 数字指标 | 28-36px | 760 |

规则：

- 不使用负 letter-spacing。
- 不用 viewport 宽度缩放字体。
- 卡片内标题不超过 2 行。
- 中文长文本允许自动换行，禁止横向溢出。

### 4.4 间距与布局

桌面端：

- 页面左右内边距：24-36px。
- 模块间距：20-24px。
- 卡片内边距：16-20px。
- 紧凑信息行间距：8-12px。
- 详情页主栏和侧栏间距：20px。

移动端：

- 页面左右内边距：16px。
- 底部导航安全区：包含 `env(safe-area-inset-bottom)`。
- 卡片内边距：14-16px。
- 主要按钮高度：不低于 44px。

## 5. 总览页设计

### 5.1 页面目标

总览页只回答一个问题：

> 今天最该处理什么？

它不是所有模块的入口堆叠，而是一个“购车节奏中枢”。

### 5.2 桌面布局

结构：

```text
顶部：页面标题 + 账号/全局操作

第一层：今日结论条
  左：当前推荐动作
  中：指标倒计时 / 候选数量 / 未关闭红线
  右：刷新 AI 分析 / 生成报告

第二层：三列工作区
  左：重点候选
  中：今日待办
  右：价格与时间线提醒

第三层：用车画像摘要 + 最近 AI 任务
```

今日结论条示例：

```text
当前节奏：继续观察，不急于成交
理由：i6 二手价格仍高，ES6/7X 需补三电质量证据，7-8 月还有新车权益变化窗口。
下一步：优先复核 2 台二手 i6 与 1 台 ES6 的 SOH、维保和合同承诺。
```

设计要求：

- 今日结论条使用白底卡片，不做 hero。
- 主结论一行醒目，理由和下一步分两行。
- 右侧最多两个按钮，避免操作噪音。

### 5.3 移动布局

结构：

```text
今日结论卡
指标倒计时
3 个关键指标
今日待办
重点候选
价格/新车提醒
```

交互：

- 今日结论卡可展开查看理由。
- 待办项左滑可标记完成或稍后。
- 点击候选直接进入单车详情。

## 6. 用车画像设计

### 6.1 页面目标

让用户清楚知道：

1. 当前系统按什么偏好判断；
2. 这个画像影响哪些页面；
3. 最近偏好发生了什么变化。

### 6.2 交互结构

画像页分三块：

1. **当前画像卡**
   - 城市；
   - 指标到期；
   - 预算；
   - 能源偏好；
   - 核心优先级；
   - 排除项；
   - i6 标尺。
2. **画像编辑抽屉**
   - 乘坐人数；
   - 场景；
   - 预算；
   - 能源；
   - 续航；
   - 车身；
   - 优先级；
   - 必须满足；
   - 不能接受。
3. **画像历史时间线**
   - 修改时间；
   - 修改内容；
   - 修改原因；
   - 是否为当前默认。

### 6.3 总览页中的画像

总览不展示完整表单，只展示“画像摘要胶囊”：

```text
北京 · 2 人 · 纯电优先 · 24-31 万 · i6 标尺 · 前排舒适/NVH 优先
```

点击“修改画像”打开抽屉，而不是把完整表单常驻首页。这样首页会更干净。

## 7. 发现页设计

### 7.1 页面目标

发现页负责找“值得进入候选尽调的对象”，但不做深度决策。

页面顶部：

- 画像摘要；
- 数据更新时间；
- 刷新按钮；
- 筛选入口。

顶部切换：

```text
[新车观察] [二手车源]
```

### 7.2 新车观察

卡片信息层级：

1. 车型图片。
2. 车型名 + 适配度。
3. 发布时间/预计上市时间。
4. 价格区间。
5. 续航/电池/能源形式。
6. 为什么值得看。
7. 主要不确定性。
8. 操作：加入新车候选、车型页、资讯。

卡片状态标签：

- 近期发布；
- 即将上市；
- 热门车型；
- 重点车型；
- 纯电；
- 待试驾；
- 权益待确认。

去重规则视觉化：

- 同一车型只显示一张主卡。
- 不同版本进入详情页的“版本列表”。
- 如果出现多来源，卡片底部显示“3 个来源”，点击展开。

新车详情结构：

```text
车型总览
版本与价格
上市/权益/改款时间线
质量与首批风险
和 i6 的预期差异
下一步：等试驾 / 加入候选 / 暂不关注
```

### 7.3 二手车源

卡片信息层级：

1. 车源图片。
2. 标题 + 车源类型。
3. 报价 + 新车参考价。
4. 上牌时间、里程、过户、城市。
5. 卖方/商家。
6. 保障口径。
7. 初步风险。
8. 操作：加入尽调、打开车源、追踪价格。

风险摘要不超过 3 条，多余进入详情。

车源类型标签：

- 懂车帝官方直营；
- 懂车帝自营；
- 个人直卖；
- 第三方商家；
- 品牌官方认证；
- 未核实。

二手车源空状态：

```text
当前画像下没有找到合适纯电车源。
可以扩大城市、提高预算、放宽里程，或手动粘贴懂车帝车源链接。
```

## 8. 候选尽调设计

### 8.1 页面目标

候选尽调页回答：

> 哪台车最值得继续推进？哪台车卡在哪个风险上？

### 8.2 列表与看板

顶部：

- 搜索；
- 类型筛选；
- 阶段筛选；
- 风险筛选；
- 质量状态筛选；
- 排序。

视图切换：

```text
[列表] [阶段]
```

列表视图适合比较信息密度；阶段视图适合长期推进。

阶段列：

1. 观察中；
2. 待补证；
3. 待试驾；
4. 待谈价；
5. 可成交；
6. 已放弃。

候选卡片必须展示：

- 对象类型；
- 车型/车源名；
- 当前价格；
- 风险等级；
- 质量可信度；
- 未关闭红线数；
- 下一步任务；
- 最近更新时间。

### 8.3 候选详情桌面布局

推荐采用三栏中的“主栏 + 右侧决策栏”：

```text
左侧主栏 65%
  车辆概览
  质量与三电
  信息墙
  风险闭环
  成本与价格
  试驾复盘

右侧决策栏 320-360px
  当前结论
  风险分
  质量可信度
  未关闭红线
  下一步任务
  主要操作
```

布局规则：

- 主栏 `min-width: 0`，避免图片挤压侧栏。
- 图片容器固定比例，使用 `object-fit: cover` 或 `contain`。
- 右侧栏只在桌面 sticky，窄屏下移动到顶部。
- 不在卡片里嵌套大卡片。

### 8.4 候选详情移动布局

结构：

```text
顶部结论卡
车辆图片
关键指标
分段导航：概览 / 质量 / 风险 / 信息 / 成本 / 试驾
内容区
底部固定操作：补证 / 问商家 / 报告
```

移动端重点：

- 先给结论，再给细节。
- 上传截图入口必须在信息墙模块顶部固定可见。
- 不使用横向表格展示关键对比。

## 9. 质量与三电模块设计

### 9.1 页面目标

质量模块必须让用户快速判断：

1. 这款车车系级质量是否可靠；
2. 这台具体车的三电证据是否齐全；
3. 哪些数据只是线索；
4. 下一步要补什么。

### 9.2 模块结构

顶部结论：

```text
质量可信度：中
三电风险：未知
证据完整度：42%
主因：缺少 SOH、4S 维保、故障码和三电质保截图。
```

下方证据分组：

1. 官方召回/缺陷；
2. 投诉销量比；
3. 第三方质量研究；
4. 车主口碑；
5. 单车证据。

每个证据卡显示：

- 可信度等级；
- 状态；
- 摘要；
- 来源；
- 更新时间；
- 对当前决策影响；
- 下一步动作。

### 9.3 状态设计

| 状态 | 标签 | 视觉 |
|---|---|---|
| 有证据 | 有证据 | 绿色浅底 |
| 待核验 | 待核验 | 琥珀浅底 |
| 缺失 | 缺失 | 灰色浅底 |
| 冲突 | 证据冲突 | 红色浅底 |

注意：

- `SOH 0%` 不能显示为有数据。
- 缺数据时卡片边框不使用绿色。
- “AI 线索”要和“官方事实”分开。

### 9.4 交互

主操作：

- AI 刷新质量数据；
- 上传检测报告；
- 复制问商家清单；
- 标记为已核验；
- 关联到风险。

AI 刷新期间：

```text
正在检索官方召回、投诉销量比、质量研究和单车证据线索...
```

失败状态：

```text
质量检索失败：数据源不可访问。
可以重试，或先上传检测报告/车源截图作为证据。
```

## 10. 信息墙设计

### 10.1 页面目标

信息墙是证据入口，不是普通备注区。

它需要支持：

- 快速上传；
- AI 提取；
- 人工确认；
- 字段回填；
- 风险关联；
- 来源追踪。

### 10.2 上传区

桌面：

```text
拖拽/选择图片、报告、截图
粘贴文本或链接
```

移动：

```text
上传截图
拍照
粘贴文字
粘贴链接
```

上传后立即生成条目，不等待 AI。

### 10.3 信息条目

每条信息展示：

- 类型图标；
- 标题；
- 来源；
- 时间；
- 缩略图；
- AI 状态；
- 已关联风险；
- 已回填字段。

AI 结果分四段：

1. 识别事实；
2. 可回填字段；
3. 新发现风险；
4. 下一步问题。

### 10.4 回填确认抽屉

结构：

```text
字段名 | 当前值 | AI 识别值 | 来源 | 操作
```

操作：

- 应用；
- 忽略；
- 编辑后应用；
- 关联证据但不回填。

规则：

- 核心字段不允许自动覆盖。
- 应用后字段旁显示来源标记。
- 重新分析不会删除旧结果。

## 11. 风险闭环设计

### 11.1 风险卡片结构

每条风险必须包含：

- 风险等级；
- 状态；
- 标题；
- 触发原因；
- 需要什么证据；
- 关联证据；
- 下一步动作；
- 操作按钮。

风险状态：

- 待核验；
- 已证实；
- 已排除；
- 已写入合同；
- 用户接受；
- 证据冲突。

### 11.2 红线风险展示

红线风险在三个地方出现：

1. 总览今日待办；
2. 候选详情右侧决策栏；
3. 决策报告顶部。

红线风险不要用大面积红色背景，只使用：

- 红色标签；
- 浅红边框；
- 明确阻断文案。

示例：

```text
暂不建议下订
原因：SOH 缺失、三电质保未确认、商家承诺未写入合同。
```

## 12. 商家档案设计

### 12.1 页面目标

商家页要从“卖方名称列表”升级为“交易可信度档案”。

### 12.2 商家卡片

展示：

- 商家名称；
- 类型；
- 城市；
- 平台身份；
- 关联车源数量；
- 风险数量；
- 最近背调时间；
- 核心承诺状态。

### 12.3 商家详情

结构：

```text
商家概览
关联车源
承诺清单
背调信息
风险记录
待问问题
```

承诺清单字段：

- 承诺内容；
- 来源；
- 是否截图；
- 是否写进合同；
- 是否已核验。

关键规则：

- “理想官方认证”“懂车帝平台认证”“商家自称官方认证”必须分开。
- 未合同化的承诺不能关闭风险。

## 13. 对比页设计

### 13.1 页面目标

对比页不是参数表，而是帮助用户做取舍。

顶部先给结论：

```text
最接近 i6：理想 i6 二手
质量证据最完整：极氪 7X
风险最高：某二手 ES6，原因是 SOH 和质保缺失
当前最适合动作：继续等 i6 二手价，补证 ES6
```

### 13.2 对比维度

固定维度：

- 综合匹配；
- i6 体感接近度；
- 3 年真实成本；
- 质量与三电；
- 智驾/车机；
- 舒适/NVH；
- 价格安全垫；
- 未关闭红线；
- 下一步。

展示方式：

- 桌面端使用横向对比表。
- 移动端使用候选间切换，不使用横向滚动大表。

## 14. 试驾设计

### 14.1 试驾前

生成试驾脚本：

- 城市低速；
- 井盖/减速带；
- 快速路；
- 高速 NOA；
- 座椅通风/按摩；
- 车机语音；
- 空调和媒体；
- 停车/转弯半径。

### 14.2 试驾后

记录结构：

- 总体感受；
- 和 i6 相比；
- 座椅；
- 静音；
- 底盘；
- 转向/刹车；
- 车机；
- 智驾；
- 不舒服的点；
- 是否愿意再试。

评分必须配文字理由。

## 15. 报告页设计

### 15.1 页面目标

报告页是成交前最后一道关。

报告顶部结论：

- 可买；
- 可谈但需补证；
- 继续等；
- 建议放弃。

### 15.2 报告结构

```text
最终结论
适配画像
价格与成本
质量与三电
车况与权益
商家与合同
试驾与体感
未关闭红线
下一步清单
证据来源
```

红线未关闭时：

- 禁止展示“建议购买”。
- 主按钮变为“补齐红线证据”。

## 16. AI 任务交互

### 16.1 全局 AI 状态

所有 AI 任务使用统一状态组件：

| 状态 | 文案 |
|---|---|
| 排队中 | 已加入分析队列 |
| 运行中 | 正在分析 |
| 成功 | 已生成待确认结果 |
| 失败 | 分析失败，查看原因 |
| 备用模型 | Gemini 不可用，已使用 DeepSeek |
| 本地兜底 | AI 不可用，已使用本地规则 |

### 16.2 错误展示

错误必须明确：

```text
AI 分析失败：Gemini API Key 未配置。
下一步：检查服务端环境变量，或切换 DeepSeek。
```

禁止：

```text
Gemini 暂不可用。
```

### 16.3 结果展示

AI 结果分层：

- 事实；
- 推断；
- 风险；
- 建议动作；
- 来源。

所有 AI 结果都显示 provider 和时间。

## 17. 组件规范

### 17.1 按钮

按钮层级：

- 主按钮：当前页面最重要动作，每个模块不超过 1 个。
- 次按钮：编辑、刷新、导出。
- 文本按钮：查看详情、打开来源。
- 危险按钮：删除、放弃候选。

规则：

- 按钮文字不超过 8 个汉字，必要时换成图标 + tooltip。
- 移动端主要按钮满宽或双按钮平分。
- 不用大段文字做按钮。

### 17.2 标签

标签类型：

- 对象标签：新车、二手、手动。
- 状态标签：待核验、已证实、冲突、已关闭。
- 来源标签：官方、投诉销量比、AI 线索、单车证据。
- 适配标签：i6 标尺、纯电、北京可上牌。

规则：

- 同一行标签最多 4 个，超出折叠。
- 颜色应服务于状态，不做装饰。

### 17.3 卡片

卡片使用场景：

- 候选；
- 车源；
- 证据；
- 风险；
- 任务；
- 商家。

卡片不用于整页 section 包裹再嵌套卡片。

卡片结构：

```text
顶部：标签/状态
主体：标题 + 关键数据
说明：一句原因或风险
底部：来源/更新时间 + 操作
```

### 17.4 表格

桌面可以使用表格，但需要：

- 列宽固定或最小宽度；
- 文本换行；
- 关键状态用标签；
- 数字右对齐。

移动端表格转为分组卡片。

## 18. 响应式规则

### 18.1 断点

```css
desktop: >= 1180px
tablet: 768px - 1179px
mobile: < 768px
```

### 18.2 桌面

- 左侧导航固定宽度 232px。
- 主内容最大宽度不强制居中，保持工作台感。
- 候选详情使用主栏 + 侧栏。

### 18.3 平板

- 侧栏可收缩。
- 详情页右侧决策栏下移。
- 卡片 grid 至少 2 列。

### 18.4 手机

- 底部导航。
- 页面标题区收紧。
- 主要操作放在页面内或底部固定栏。
- 图片宽度 100%，固定比例。
- 不出现横向滚动，除非是短标签栏。

## 20. 实施优先级

### 第一阶段：布局和导航

1. 桌面导航收敛为 7 个主入口。
2. 移动端底部导航收敛为 5 个入口。
3. 总览改成“今日结论 + 待办 + 候选 + 时间线”。
4. 发现页合并新车和二手，使用 segmented control。
5. 候选详情修复 PC 布局，建立主栏 + 决策栏。

### 第二阶段：证据与质量组件

1. 重构质量与三电模块。
2. 重构信息墙条目和 AI 回填确认抽屉。
3. 统一风险卡片状态。
4. 建立 AIJob 状态组件。

### 第三阶段：决策和报告

1. 红线检查视觉组件。
2. 决策报告页面。
3. 对比页结论优先改造。
4. 试驾 i6 标尺复盘。

## 21. 视觉验收清单

上线前逐项检查：

1. 桌面候选详情不重叠、不横向溢出。
2. 移动端底部导航不超过 5 个入口。
3. 新车和二手在发现页对象类型清楚。
4. 信息墙上传图片有预览。
5. 质量卡片缺数据时不显示绿色成功状态。
6. AI 失败显示具体原因和重试入口。
7. 红线风险在总览、详情、报告三处一致。
8. 所有主要按钮高度满足移动端点击要求。
9. 标签不超过 4 个一行，超出折叠。
10. 中文长文本不撑破卡片。
11. 图片保持比例，不挤压文字。
12. Tab 切换保留滚动位置。

## 22. 和当前实现的差异

当前实现已经有较完整的功能基础，但 V1.3 设计需要做这些调整：

1. 首页不再常驻完整画像表单，改为画像摘要 + 编辑抽屉。
2. 新车观察和二手车源在移动端合并到发现页。
3. 候选详情从当前内容堆叠改为“主栏 + 决策栏”。
4. 质量与三电从普通信息卡升级为证据分层模块。
5. 信息墙从列表升级为 AI 证据工作台。
6. 风险从单独页面弱化为详情和报告中的闭环组件。
7. AI 结果必须显示 provider、状态、失败原因和确认回填。

## 23. Definition of Done

交互与视觉设计可认为完成，当且仅当：

1. 用户能在总览 10 秒内知道今天最重要的动作。
2. 用户能清楚区分新车车型、二手车源和候选尽调。
3. 候选详情能在桌面和手机上稳定阅读。
4. 质量与三电模块能表达“有证据、缺失、待核验、冲突”。
5. 信息墙能支持截图上传、AI 分析和人工确认。
6. 红线风险在成交前被明确阻断。
7. 视觉风格克制、专业、没有装饰噪音。
8. 所有关键页面都有空状态、加载态、错误态和成功态。
